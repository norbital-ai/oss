# Norbital OSS

The open-source workspace framework, UI system, and shared libraries used by Norbital.

Starter workspaces live in their own repository:
[**norbital-ai/templates**](https://github.com/norbital-ai/templates).

## Packages

- [`@norbital-ai/bolt`](./packages/bolt) — tenant workspace authoring SDK, compiler, runtime, and
  client
- [`@norbital-ai/bolt-server`](./packages/bolt-server) — self-host server around the Bolt bundle
- [`@norbital-ai/ui`](./packages/ui) — Svelte component library and design tokens
- [`@norbital-ai/std`](./packages/std) — common schema, date, CEL, finance, collection contract, and
  utility modules
- [`@norbital-ai/doctor`](./packages/doctor) — fixed static rule packs used by `bolt check`
- [`@norbital-ai/providers`](./packages/providers) — host-registered integration and inference providers
- [`@norbital-ai/app-shell`](./packages/app-shell) — native iOS and Android shell and the `norbital-app` CLI

Templates are authored in [`norbital-ai/templates`](https://github.com/norbital-ai/templates),
which is also where `refs/heads/templates/*` is published from. This repository holds no template
source.

## Development

Requires Node.js 26+ and pnpm 11 (the workspace pins `pnpm@11.22.0`).

```sh
pnpm install
pnpm check
```

Every compiled package builds through Turbo during `pnpm pack`; Bolt and UI use `svelte-package`,
while the TypeScript-only packages use `tsc`. Publication checks copy source into an isolated
workspace, materialize its frozen dependency graph offline, and test cold prepack there. The prior
`pnpm install` must have populated the dependency store. Archive contents and declarations are
validated before the temporary workspace and archives are removed. Live package output is preserved.
Consumers install released packages from the configured registry; no consumer reads this repository
through a sibling path.

All seven public packages share the workspace release version. Bump the complete set before a release;
the workflow publishes missing immutable versions and skips versions already on the registry.
Consumers commit their matching manifest and lockfile updates after publication. See
[`RELEASING.md`](./RELEASING.md) for the release workflow.

Template source is published as deterministic root-projected Git refs, each carrying its own
`norbital.template.json` and its own committed `pnpm-lock.yaml`. There is no platform release, no
builder image, and no tenant-runtime image; the Convert service publishes its own OCI image. The
provider-neutral distribution contract is documented in
[`release/README.md`](./release/README.md).
