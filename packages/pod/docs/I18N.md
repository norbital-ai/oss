# Internationalization

Every Norbital surface — the website, the Core platform, and each tenant workspace — localizes into
English (`en`, the source of truth) and Simplified Chinese (`zh`). This document describes the
runtime, the catalog merge, and the server surfaces.

## Runtime

The pure runtime lives in `@norbital-ai/std/i18n` (`packages/std/src/i18n/`):

- `defineMessages(en, zh)` — defines one catalog pair; TypeScript enforces that `zh` carries exactly
  the keys of `en`.
- `translate(catalogs, locale, key, vars)` — locale → en → key fallback, with `{name}` interpolation.
- `hasKey(catalogs, key)` — distinguishes "not in the catalog" from "translated to the raw key",
  used by label overrides that fall back to authored text.
- `createI18n(catalogs, locale)` — the non-reactive runtime for server code:
  `{ locale, intlLocale, t, has, setLocale }`.
- `Locale = 'en' | 'zh'`, `INTL_LOCALE = { en: 'en-US', zh: 'zh-CN' }`, `parseLocale` (BCP-47),
  `pickLocale` (Accept-Language candidates), `storedLocale`/`storeLocale` (`norbital.locale`),
  `setHtmlLang`.

## Client context

The Svelte context lives in `@norbital-ai/ui/i18n` (`packages/ui/src/i18n/`):

- `provideI18n(catalogs, initialLocale?)` — installs the runtime for a subtree; locale resolves
  stored choice → browser languages → en. Called once from `pod-app.svelte`.
- `useI18n<Keys>()` — `{ locale, intlLocale, t, has, setLocale }`; `t` reads `$state` on every call,
  so destructured `t` stays reactive across locale switches.
- `setGlobalLocale(locale)` — fallback locale for components rendered without a provider.

Components import `useI18n` from `#lib/i18n` inside the ui package and from
`@norbital-ai/ui/i18n` outside it. The key union for the pod chrome is `PodUiKeys`
(`PodKeys | UiKeys`, from `packages/pod/src/i18n/index.ts`); tenant app files use the generated
`TenantI18nKeys` from `$pod/i18n-keys`.

## Catalogs

| Catalog | Location | Keys |
| --- | --- | --- |
| ui component library | `packages/ui/src/i18n/messages/*.messages.ts` | `common.*`, `table.*`, `kanban.*`, `form.*`, `dataRenderer.*`, `misc.*` |
| pod chrome + server | `packages/pod/src/i18n/messages.ts` | `pod.*`, `server.*`, `email.*`, `identity.*` |
| tenant overrides | tenant `src/i18n/messages.{en,zh}.json` | tenant-owned, plus overrides of any platform key |

The build-time merge (`packages/pod/src/vite/index.ts`, `virtual:pod/i18n`) is
`pod chrome + ui ← tenant JSON`. Tenant catalogs are discovered and validated by the compiler
(`packages/pod/src/vite/compiler/index.ts`, `discoverI18n`): both files required together, exact key
parity, JSON shape errors and stray files reported as structural diagnostics. The same pass
generates `.norbital/generated/i18n-keys.ts` (`TenantI18nKeys`).

## Client chrome

`pod-app.svelte` calls `provideI18n(i18nMessages)` (catalogs arrive from the generated client entry,
which imports `virtual:pod/i18n`). The shell resolves sidebar labels per locale through
`app.<appId>.title` / `app.<groupId>.title` catalog keys (chokepoint in
`packages/pod/src/ui/shell/workspace-navigation.ts`, `resolveNavigationLabel`), falling back to the
static `<svelte:head>` metadata. App metadata in `<svelte:head>` stays static English — the compiler
reads it for app identity.

## Server surfaces

Server code has no Svelte context. `packages/pod/src/i18n/index.ts` exports:

- `podMessages` — the chrome catalog pair, for merging or direct use.
- `serverI18n(acceptLanguageOrLocales)` — `createI18n(podMessages, pickLocale(...))`.

Identity pages (`packages/pod/src/host/identity-pages.ts`) and transactional email
(`email-otp.ts`, `invitation.server.ts`) thread a `ServerI18n` through their functions, resolving
the locale from the request: `?lang=` wins, then `Accept-Language` (see `identityRequestI18n` in
`email-otp.ts` and `requestI18n` in `server/i18n.ts`). Wire-level HTTP error literals and
infrastructure log lines stay English by design.

## Tenant authoring

Tenants write `src/i18n/messages.en.json` + `messages.zh.json` (exact key parity, enforced by the
compiler) and translate app copy with `useI18n<TenantI18nKeys>()`. See the
`authoring-tenant-workspace` skill (`references/internationalization.md`) and the website docs page
`docs/internationalization`.
