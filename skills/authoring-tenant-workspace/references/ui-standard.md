# Template UI standard

Review checklist for every template page. Rule homes: [app-structure.md](app-structure.md), [layout-and-scrolling.md](layout-and-scrolling.md), [typography.md](typography.md), [controller-surfaces.md](controller-surfaces.md), [internationalization.md](internationalization.md).

1. **Two scaffolds, primitive roles, co-location & single-owner chrome:** `AppShell` (icon, 1–3 word title never repeating workspace name, ≤90-char description ending in a period) for lists/boards/dashboards/reports/portals; `RecordShell` (title `record_label`/UUID, singular overline, subtitle fields, owned header/footer/scroll) for any single record including settings/singletons. Match primitive to role: `Table`/`Board` for independent collections, toolbar `⚡` for collection actions and exports (never loose export buttons inside `+representation.svelte`), `+representation.svelte` for single-record data collection / fixed structured display, and the shared `@norbital-ai/ui` `Timeline` (also used by `RecordShell`'s History widget and `ApprovalPanel`) for time-series / dated-history / change logs. Co-locate single-purpose custom UI beside its owning `+renderer.svelte`, `+representation.svelte`, or `+<page>.page.svelte`, and model-specific services beside `+model.ts` (e.g. `service/`); place modules in `src/lib/` only when genuinely reused. Every primitive owns its own chrome slots (`Table`/`Board` `toolbar.{title,description,actions}`, `Section` `{title,icon,hint,actions}`, `Field` `description`), never bolt duplicate headings, helper text, action bars, or standalone `<DescriptionHint>` icons outside a primitive that already owns that slot.
2. **One concern & one scroll per view:** at most one `Table` or `Board` per page/tab (`check/single-data-view`); no `AppShell variant="full"` directly wrapping a single `Table` (`check/app-shell-inset`); one scroll owner per axis (`check/scroll-ownership`).
3. **Navigation, view toggles & scope:** use `Tabs` (never `Combobox` or `<select>`) for sub-report switching; when one tab switches alternate views of the same collection (Timeline / Table / Board), place compact icon-only toggles with tooltips in `toolbar.trailing` right beside `+ New`; reserve `AppShell.actions` strictly for page-wide scope pickers governing every tab. Never duplicate a child record's tabs (e.g. variations/transactions filed inside an order/contract) as redundant top-level tabs on the parent hub, and never place a standalone heading above a pane whose enclosing tab already names it. Use `keep_alive: true` on form tabs and heavy client-viewer tabs, and cache client-converted viewer bundles in browser storage (`CacheStorage`/`IndexedDB` + LRU) with drag-guarded modifier/Inspect selection.
4. **Rows, scope & representations:** row click opens that row's record (or `on_open`); no links or loose buttons inside cells — use row `actions`. Every tab in a scoped app filters its view by the shared scope and opens `Sheet` + `RecordShell mode="create"` with the parent FK in `values` (closing on committed/`pending_approval`). Inside `+representation.svelte`, lay out fields in `<Grid minimum="compact" gap="md">` (never default `minimum="card"` on `<Grid as="dl">` or 1-field-per-row `<Stack>` inside custom composite/union `editors`/`viewers` snippets), place compact scalar fields together before `wide` (`wide: true` on `<Field>`, never `class="col-span-full"`) fields so rows pack cleanly without orphan cells, avoid 1-field sections, and keep `<Field>` mounted for attributes omitted by narrow outputs (Bolt renders an in-place redacted fallback so redaction never alters layout — never omit redacted fields with `{#if commercial}`). Always hide innately scoped parent FKs (`project_id`, `entity_id`, `machine_id`, etc.) whenever prefilled in `view.values` or already stored on `record` (never render a redundant parent field inside a scoped child sheet; show a parent picker only on an unscoped standalone create), omit unnecessary sequence/counter columns (`submission_no`, `trial_count`) from child views/tables, lock cell-fixed keys (showing read-only projected context beside them), scope dependent `<Picker>` controls with `where`, never expose `transform`-computed fields as inputs, and replace generic `Empty array` / `Additional properties` editors with domain pickers (`TimeInput`/`TimeRangeInput`, schema-driven fields).
5. **Typed kinds & controlled tables:** use `Show`/`Field` kinds (`date` medium, `instant` medium+short time, `money` `CODE 1,234.00`, trimmed decimals, empty `—`), coloured `StateBadge` for states and neutral `Badge` for enums/tags. Controlled `<Table of={rows}>` MUST declare `kind` (`money`/`decimal`/`int`/`date`/`instant`), `align: 'end'` on numeric/money fields, and merge `currency` + `amount`/`value`/`total`/`balance`/`limit` into one `kind: { kind: 'money', currency: '...' }` column (`check/controlled-table-kinds`).
6. **Controls & sizing:** every input carries a visible label (never placeholder-only); raw `<select>` is banned (`check/raw-select`); size controls from parent layout — never fixed `w-*`/`h-*`/`min-w-*`/`min-h-*` on `Input`/`Combobox`/`TimeInput`/`Bound` (`check/self-sized-control`).
7. **Surfaces, media, theming, behaviors, typography & icons:** prefer `<Surface>` (`tone="card|subtle|muted|lane"`, `padding`, `radius="control"`) and semantic tokens (`surface-*`, `content-*`, `border-*`, `tone-*`, `rounded-control`/`rounded-inset`/`rounded-overlay`) with zero `dark:` modifiers or raw palette/hex colors; render workspace/record images with `<Image>` from `@norbital-ai/ui` (never raw `<img>`) so every photo gets our standard animated mosaic placeholder and dissolve; set workspace-wide `theme: { palette, accent, radius }` in `src/+workspace.ts`; **never hand-roll UI interaction behaviors** — compose custom interactive widgets and reactive state from `@norbital-ai/ui/behaviors` (navigation/menus/trees/lists/fuzzy search, selection/grid/inline-edit/drag/reorder/transfer/resize/panel-group/slider/canvas/drawer, floating/dismiss/focus-trap/hover-intent/presence/findable/announce/viewport, switch/radio-group/toggle-group/checkbox-group/number-input/rating/token-input/trigger-menu/file-dropzone/password-input/color-picker/image-cropper/carousel/timeline/waterfall/date-time/pin, shortcuts/history/undo/clipboard/stick-to-bottom/pagination, `watch`/`Debounced`/`use_debounce`/`PersistedState`/`create_cookie_storage`/`virtual_list`, and `register_control` on every custom widget — see `references/behaviors-and-composition.md` and `bolt-contract` `behaviors.md`); typography roles only (`check/typography-tokens`); Lucide `<Icon>` only — no raw `▲▼ℹ⚠` (`check/raw-unicode-icons`).
8. **CTAs, summaries & charts:** at most one `Button variant="brand"` per view (surface primary state + next workflow CTA directly, never buried in ⚡); cap summary strips at 4–5 KPIs (omit zero-value tiles/orphan rows); never wrap `<Chart>` in `<Bound size="viewport">` (`check/chart-viewport` — use ~16–20rem panel height).
9. **States, one-entity Save & i18n:** `EmptyState` + view skeletons; one Save per view — parent + owned children treated as one entity use an in-place editable data matrix (`ChildGrid save="parent"`, `Rows`, or embedded matrix via `form.queue_children` on create + `Form` `acts` on update, with create/update parity) committed in one Save, never a nested `<Table>` opening child sheets, immediate per-row `ctx.act()` calls, or read-only create previews; catalog keys cover all visible text in every declared language (`check/untranslated-text`); verify desktop + phone widths and both light/dark themes.
