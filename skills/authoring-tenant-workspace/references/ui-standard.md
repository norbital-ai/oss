# Template UI standard

Review checklist for every template page. Rule homes: [app-structure.md](app-structure.md), [layout-and-scrolling.md](layout-and-scrolling.md), [typography.md](typography.md), [controller-surfaces.md](controller-surfaces.md), [internationalization.md](internationalization.md).

1. **Two scaffolds, primitive roles & single-owner chrome:** `AppShell` (icon, 1–3 word title never repeating workspace name, ≤90-char description ending in a period) for lists/boards/dashboards/reports/portals; `RecordShell` (title `record_label`/UUID, singular overline, subtitle fields, owned header/footer/scroll) for any single record including settings/singletons. Match primitive to role: `Table`/`Board` for independent collections, toolbar `⚡` for collection actions and exports (never loose export buttons inside `+representation.svelte`), `+representation.svelte` for single-record data collection / fixed structured display, and the shared `@norbital-ai/ui` `Timeline` (also used by `RecordShell`'s History widget and `ApprovalPanel`) for time-series / dated-history / change logs. Every primitive owns its own chrome slots (`Table`/`Board` `toolbar.{title,description,actions}`, `Section` `{title,icon,hint,actions}`, `Field` `description`), never bolt duplicate headings, helper text, action bars, or standalone `<DescriptionHint>` icons outside a primitive that already owns that slot.
2. **One concern & one scroll per view:** at most one `Table` or `Board` per page/tab (`check/single-data-view`); no `AppShell variant="full"` directly wrapping a single `Table` (`check/app-shell-inset`); one scroll owner per axis (`check/scroll-ownership`).
3. **Navigation & scope:** use `Tabs` (never `Combobox` or `<select>`) for view/sub-report switching; reserve `AppShell.actions` strictly for page-wide scope pickers governing every tab.
4. **Rows & links:** row click opens that row's record (or `on_open`); no links or loose buttons inside cells — use row `actions`. Parent-scoped table New opens `Sheet` + `RecordShell mode="create"` with parent in `values` and closes on committed/`pending_approval`.
5. **Typed kinds & controlled tables:** use `Show`/`Field` kinds (`date` medium, `instant` medium+short time, `money` `CODE 1,234.00`, trimmed decimals, empty `—`), coloured `StateBadge` for states and neutral `Badge` for enums/tags. Controlled `<Table of={rows}>` MUST declare `kind` (`money`/`decimal`/`int`/`date`/`instant`), `align: 'end'` on numeric/money fields, and merge `currency` + `amount`/`value`/`total`/`balance`/`limit` into one `kind: { kind: 'money', currency: '...' }` column (`check/controlled-table-kinds`).
6. **Controls & sizing:** every input carries a visible label (never placeholder-only); raw `<select>` is banned (`check/raw-select`); size controls from parent layout — never fixed `w-*`/`h-*`/`min-w-*`/`min-h-*` on `Input`/`Combobox`/`TimeInput`/`Bound` (`check/self-sized-control`).
7. **Surfaces, media, theming, behaviors, typography & icons:** prefer `<Surface>` (`tone="card|subtle|muted|lane"`, `padding`, `radius="control"`) and semantic tokens (`surface-*`, `content-*`, `border-*`, `tone-*`, `rounded-control`/`rounded-inset`/`rounded-overlay`) with zero `dark:` modifiers or raw palette/hex colors; render workspace/record images with `<Image>` from `@norbital-ai/ui` (never raw `<img>`) so every photo gets our standard animated mosaic placeholder and dissolve; set workspace-wide `theme: { palette, accent, radius }` in `src/+workspace.ts`; compose custom interactive widgets and reactive state from `@norbital-ai/ui/behaviors` (`create_disclosure`, `create_accordion`, `create_selection`, `create_roving_focus`, `create_typeahead`, `create_listbox`, `create_tree`, `create_overflow`, `create_reorder`, `create_resize`, `create_slider`, `create_dismiss`, `create_focus_trap`, `create_shortcuts`, `create_stick_to_bottom`, `create_pagination`, `create_clipboard`, `create_field`, `create_floating`, `portal`, `create_pin_input`, `create_date_field`, `create_time_field`, `create_calendar`, `watch`, `Debounced`, `use_debounce`, `PersistedState`, `virtual_list`, `register_control`) rather than adding external UI/utility packages or hand-rolling keyboard/ARIA/overflow/overlay logic; typography roles only (`check/typography-tokens`); Lucide `<Icon>` only — no raw `▲▼ℹ⚠` (`check/raw-unicode-icons`).
8. **CTAs, summaries & charts:** at most one `Button variant="brand"` per view (surface primary state + next workflow CTA directly, never buried in ⚡); cap summary strips at 4–5 KPIs (omit zero-value tiles/orphan rows); never wrap `<Chart>` in `<Bound size="viewport">` (`check/chart-viewport` — use ~16–20rem panel height).
9. **States, one-entity Save & i18n:** `EmptyState` + view skeletons; one Save per view — parent + owned children treated as one entity use an in-place editable data matrix (`ChildGrid save="parent"`, `Rows`, or `Form` `acts`) committed in one Save, never a nested `<Table>` opening child sheets or immediate per-row `ctx.act()` calls; catalog keys cover all visible text in every declared language (`check/untranslated-text`); verify desktop + phone widths and both light/dark themes.
