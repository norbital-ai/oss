# Internationalization

- English (`'en'`) is always the workspace basis (`src/i18n/+messages.ts`; omitting `'en'` in `src/+workspace.ts` `languages` fails `check/messages-base-en`). Default `languages: ['en']`.
- Each extra language in `languages` requires `src/i18n/+<lang>.messages.ts` mirroring base keys (`check/messages-locale-missing`, `missing`, `extra`), identical `{placeholders}` (`placeholders`), and non-empty strings (`empty`). Built-in framework translations ship for `en` and `zh`; non-native languages (e.g. `ja`, `ms`, `th`) must cover every framework key (`check/messages-framework-missing`) so no English chrome leaks.
- When `languages.length > 1`, the shell renders a Globe (`lucide:globe`) endonym picker (hidden for single-language workspaces) and `check/untranslated-text` flags raw alphabetic text nodes and literal `title`/`description`/`label`/`placeholder`/`hint`/`aria-label` attributes in `.svelte` (exempt: `<code>`, `<pre>`, `<svg>`, `aria-hidden="true"`, numbers/punctuation, ISO currency codes, units, URLs, non-visible props, `<!-- bolt-check:allow untranslated-text -->`).
- Static `t('key')`, `ctx.t('key')` and `ctx.refuse('key')` must name declared base, native `models.*`, or framework keys (`check/messages-undeclared-key`). Declarations (`Msg`) take keys, never literals; model/sync/automation/integration/custom-field kinds forbid inline `label`/`help`. Reuse platform keys (e.g. `common.save`). `ctx.t` is typed from base; derive composites in `$derived`.
- **Key conventions:** `app.<app>.title|description|tab_<name>`, `app.<group>.title`, `models.<m>.label|singular|fields.<f>|fields.<f>.<value>|help.<f>` (base humanizes names, so English only needs overrides), `automations.<name>.input.fields|help.<f>`, `integrations.<def>.configuration.fields|help.<f>`, `component.<name>`.
- **Resolution:** stored choice → browser languages → workspace `locale` (mail/SSR: `?lang=` → `Accept-Language`).
